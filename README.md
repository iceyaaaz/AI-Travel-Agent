# AI Travel Agent · Dify 旅行规划助手

基于 Dify 的旅行助手学习项目：从单 Agent 演进到显式分支的 Chatflow，实践知识库检索、外部天气 API、结构化参数提取和多轮行程参数保存。

**当前进度：按 14 步计划完成了第 1–11 步（Chatflow 搭建、知识库、天气接口、多轮行程参数保存）。完整评测尚未执行，因此本项目不提供通过率。**

## 已实现的功能

| 能力 | 实现方式 | 当前边界 |
| --- | --- | --- |
| 意图分流 | 问题分类器区分天气、知识问答、旅游规划、无关问题 | 等待行程补充时，使用 `pending_intent` 辅助路由 |
| 三城知识问答 | 沈阳、大连、天津，共 9 份文档；知识检索 → LLM → 引用回答 | 未收录事实应说明缺失，不能把标题当作答案 |
| 天气与未来预报 | OpenWeather 当前天气 → Python 提取坐标 → HTTP `/data/2.5/forecast` | 受接口返回时间范围限制；天气多轮补参尚未实现 |
| 多轮行程规划 | 参数提取、Python 合并、会话变量保存、缺参追问 | 支持补充城市/天数及更新天数；新任务状态隔离仍需加强 |
| 输出约束 | 区分资料事实与一般建议，限制编造动态票务/房价 | 行程生成目前未接入知识检索或天气查询 |

## 工作流

```mermaid
flowchart TD
    A[用户输入] --> B[问题分类器]
    B --> C[无关问题固定回复]
    B --> D[天气参数提取与完整性判断]
    D -->|缺参| E[天气信息追问]
    D -->|齐全| F[OpenWeather 当前天气]
    F --> G[Python 提取坐标与当地日期]
    G --> H[HTTP 未来预报]
    H --> I[天气结果总结与回复]
    B --> J[旅游知识检索]
    J --> K[基于上下文生成与引用回复]
    B --> L[行程参数提取]
    L --> M[合并并保存会话参数]
    M --> N{城市与天数齐全}
    N -->|否| O[标记等待行程补充并追问]
    N -->|是| P[清除等待标记并生成行程]
```

## 复现入口

1. 下载 [当前 Chatflow YAML](v3-chatflow.yml)，在 Dify 工作室导入；也提供 [应用包](exports/v3-chatflow.ifpkg)。
2. 按 [配置与复现指南](docs/SETUP.md) 设置模型、插件、自己的 OpenWeather Key，并重新绑定知识库。
3. 先执行指南中的冒烟验证，再使用 [57 条评测用例](evaluation/cases.csv) 做人工或后续 API 回归。

导出模板已清空环境变量值、会话初值和原工作区知识库绑定，不能直接导入后零配置运行。模型名称及 Dify 导出格式可能需要适配你的环境。

当前知识问答仅依据检索资料，库外城市或未收录事实应说明资料缺失；行程分支可以提供明确标注的一般建议。57 题尚未完整执行；D001 标注已知限制，D005/D006 的天气项按当前范围注明不判定。范围注释不代表这些用例已通过。当前状态见 [迭代日志](docs/ITERATION_LOG.md)。

## 技术实践

- Dify Chatflow 的意图分类、条件分支和显式工具编排。
- RAG 分块与重叠、向量/混合检索、Top K、重排及人工召回分析。
- HTTP API 参数绑定、Secret 环境变量、JSON 解析和动态城市坐标传递；借助 AI 编写 Python 节点，并对关键合并逻辑做离线测试。
- 会话状态管理、缺参追问、参数合并与多轮任务路由。
- 结合用例与可核验轨迹记录天气误路由、检索对象混淆及代码返回分支等问题；缺少证据的原因保留为待核验。

这些是项目实践内容，不代表已完成生产部署、模型训练或高并发验证。更新细节见 [变更记录](CHANGELOG.md)。
