# 配置与复现指南

## 1. 导入应用

在 Dify 工作室选择导入 DSL，上传根目录 `v3-chatflow.yml`。若你的版本使用应用包导入，可尝试 `exports/v3-chatflow.ifpkg`。模板采用导出格式 version 0.7.0；不同 Dify 版本可能提示兼容问题，请先在新应用中导入，保留原应用。

原仓库 `travel-agent.yml` 为早期 Agent，勿与当前模板混淆。

## 2. 设置模型与工具

模板依赖 DeepSeek、OpenWeather、通义插件。到插件/模型供应商页面配置自己的授权，然后逐个打开问题分类器、参数提取器、LLM 节点选择可用模型。源配置使用 `deepseek-v4-flash`；若你的账户没有该模型，选择支持对应节点能力的模型并重新验证。不要把模型名可选当作已获得调用权限。

OpenWeather 的“天气查询”节点需要在工具供应商处配置自己的 Key。该节点用于获取当前天气及城市坐标。

HTTP“OpenWeather未来预报”还需在应用顶部 ENV/环境变量面板中配置：

| 名称 | 类型 | 值 |
| --- | --- | --- |
| `OPENWEATHER_API_KEY` | Secret | 自己的 OpenWeather API Key |

环境变量与插件凭证是两个配置入口，即使使用同一 Key 也需分别绑定。不要将真实 Key 写入仓库、截图或提示词。费用和可用额度取决于自己的模型与天气服务账户。

HTTP 节点应为 GET `https://api.openweathermap.org/data/2.5/forecast`，查询参数如下：

| 参数 | 引用/值 |
| --- | --- |
| `lat` | 提取城市坐标 → lat |
| `lon` | 提取城市坐标 → lon |
| `units` | metric |
| `lang` | zh_cn |
| `appid` | 环境变量 OPENWEATHER_API_KEY |

Body 选择 none，保持 SSL 证书校验。不要将脱敏显示的星号复制成 Key。401 应检查凭证及账户权限，400 应检查 URL 和参数；不应仅凭状态码断言具体根因。

## 3. 创建并绑定知识库

新建高质量知识库，上传 `knowledge/` 全部 9 份 TXT：沈阳、大连、天津分别有景点、美食、交通住宿三个主题。知识库只提供收录的稳定事实，不提供实时票务、房源或预约余量。

学习实验中 C 库采用分块 1000、重叠 100，Embedding `text-embedding-v3`，混合检索 + `qwen3-rerank`，Top K 5，Score 阈值关闭。需要配置自己的 Embedding 和重排模型。不同解析版本产生的 Chunk 编号可能不同。

**当前导出的 Chatflow 检索节点另有覆盖配置**：多路检索、Top K 4、加权向量 0.7 / 关键词 0.3、关闭模型重排，Embedding 指向通义 `text-embedding-v3`。本次保留这一实际配置，不能将它视作已复现 C 库 Top K 5 的实验。进入“旅游知识检索”节点，重新选择你创建的知识库，并检查“召回设置”。如果改变这些参数，请记录为新的实验条件。

公开模板的 dataset_ids 已清空；未绑定前知识检索分支不能正常工作。

## 4. 核对变量与连线

会话变量初值应为：`trip_days` Number = 0；`trip_city`、`trip_preferences`、`trip_start_date`、`pending_intent` 均为 String 空值。

行程链路：参数提取 → 合并行程参数 → 变量赋值保存四项 → 行程信息是否齐全。条件是 city 非空 AND days > 0。ELSE → 标记等待行程补充 → 行程信息追问；IF → 清除等待标记 → 行程生成 → 行程最终回复。生成节点使用合并参数，而不是只使用本轮提取参数。

天气链路：参数提取 → 信息齐全判断 → 当前天气 → 提取坐标 → HTTP 预报 → 天气结果回答 → 天气最终回复。结果回答须引用 HTTP body、用户问题、查询日期与代码输出的 current_local_date。日期选择仍由模型处理；此版未增加独立日期筛选代码。

`scripts/` 保存节点源码供阅读。公开模板修复了“合并行程参数”return 缩进；你的旧在线应用若仍采用旧代码，需要手动同步这一修改。仓库更新不会自动修改 Dify 在线应用。

## 5. 冒烟验证

每组从新对话开始，先在预览运行，不必直接覆盖正式应用：

1. “帮我写 Python 排序代码”：应走无关回复。
2. “海麻线包子一定是素食吗”：应检索大连美食，依据含肉丁的文档回答不一定，并核实店家配料。
3. “张学良旧居明天下午还有多少预约名额”：应说明库中没有该动态信息。
4. “沈阳明天天气怎么样”：检查轨迹经过 HTTP 预报，城市、当地目标日期和使用数据匹配。
5. 新对话问“杭州明天天气怎么样”：检查返回城市不是写死的沈阳。
6. “杭州30天后天气怎么样”：应说明返回数据未覆盖目标日期，不能借用最近一天。
7. “帮我安排3天旅游，带父母” → “大连” → “改成2天”：应保留偏好并改为两天。
8. “明天天气怎么样” → “杭州”：目前已知可能误路由，按失败记录，不应标记通过。
